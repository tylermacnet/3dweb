Migration status

Migration report

The project ships a library of independent web components with no root component: property-listings, listing-card, listing-filters, and the iframe-to-listing listing-details, all registered by the single bundle. Phases 1–9 are complete, including focused presentation components with an adapter-backed details modal (product term for a non-modal Popover API popover="auto" element with role="dialog", autofocus, native focus return, no manual focus or dismiss code), a four-element public surface with an SSR-safe auto-wiring bundle entry, origin-restricted hidenav iframe embeds, and staging parity for external embeds via the source-independent Listing target schema; sorting is intentionally out of scope. The legacy public/test.html embed is frozen byte-identical for parity comparison, and the Phase 5 debug harness has been removed. public/index.html is staging for production on external websites and consumes only public/dist/bundle.js.

Phase 8 follow-up: details open latency

  • Problem: the popover shell painted empty (title only) for up to a second on cold opens of different listings, costing attention and traffic. The cross-origin document itself is untouchable, so all latency work stays on our side of the timeline.
  • Response: the shell now opens with a geometry-exact skeleton (aria-busy) in the click frame while the iframe navigation starts on the next animation frame; a 150ms ease-out fade/rise (opacity/transform only, disabled under prefers-reduced-motion) smooths the entry; the overlay is premounted, styled, and preconnected at idle via the optional DetailsModal.warm(); hover/focus intent prefetches the exact iframe URL through hideNavVariantOf() (deduped, skipped on Save-Data); the live document is reused on same-listing reopen and discarded to about:blank only after a 5-minute staleness window; the iframe carries fetchpriority="high". Deliberately out: prefetch-all, prerender, and speculation rules (cross-site prerender is impossible; cross-site prefetch is credentialless and cookie-gated).
  • Validation: the full repository gate passes with 35 unit tests and 78 integration tests, plus formatting, linting, type-checking, and production build.
