Migration status

Migration report

The project ships a library of independent web components with no root component: property-listings, listing-card, listing-filters, and the iframe-to-listing listing-details, all registered by the single bundle. Phases 1–8 are complete, including focused presentation components with a native-only adapter-backed details popover (Popover API popover="auto", autofocus, native focus return, no manual focus or dismiss code), a four-element public surface with an SSR-safe auto-wiring bundle entry, and origin-restricted hidenav iframe embeds; sorting is intentionally out of scope. Phases 4–5 remain under review against the parser-error, adapter-resilience, and coverage requirements.

Phase 8 review evidence

  • Architecture: four independent elements (property-listings, listing-card, listing-filters, listing-details) are registered by the single bundle; there is no root component. src/index.tsx exports configurePropertyListings(root?), auto-wires on DOMContentLoaded, observes late-added elements, and touches no document at import time (SSR-safe). Defaults are assembled once per document: a shared immutable location resolver, a fresh stateless feed per element, one popover per document, and a root element that is itself a property-listings is wired too.
  • SOLID and 2026 practices: the monolithic ListingController was split into ListingFeedLoader (feed lifecycle, cancellation, and a discriminated-union load state behind an explicit setFeed()) and ListingFilterStore (criteria plus derived visible listings/location groups, defended from caller mutation). The details overlay is a native Popover API element (popover="auto", autofocus, focus return to the triggering card via showPopover({ source }); no manual Tab trap, backdrop handler, or focus capture/restore) that returns false when popover is unsupported, so the card's cancelable listing-details-requested event leaves the anchor navigation as the progressive-enhancement fallback. resolveDetailsIframeUrl() restricts iframe sources to HTTPS on exactly the ManageBuilding canonical origin (a host base-url never widens that origin) and always forces hidenav; the feed URL is adapter-owned product policy with a fixed direct-then-proxy chain.
